Quality Control

The quality slider is shown when the target format is JPEG or WebP (both lossy). Quality ranges from 1 (maximum compression) to 100 (minimum compression). A setting of 80–90 is generally a good balance between file size and visual fidelity.

For PNG output, quality is not applicable — PNG is always losslessly encoded.

Transparency Handling

JPEG does not support transparency. When converting from a format that may have transparent pixels (PNG, WebP, GIF) to JPEG, any transparent areas are filled with the selected background color (white by default). The background color picker is only shown when this situation applies.

Format Comparison

JPEG

  • Best for photographs and complex images with many colors
  • Does not support transparency
  • Widely supported across all devices and platforms
  • File sizes are small for photographs

PNG

  • Best for graphics with sharp edges, text, and logos
  • Supports full transparency (alpha channel)
  • Losslessly encoded — no quality degradation
  • Larger file sizes than JPEG for photographs

WebP

  • Modern format developed by Google (2010)
  • Supports both lossy and lossless compression
  • Supports transparency
  • Typically 25–35% smaller than JPEG and 20–30% smaller than PNG at similar quality
  • Supported by all modern browsers (Chrome, Firefox, Safari 14+, Edge)

When to Convert

  • JPEG → WebP: if you want smaller files for web delivery and your audience uses modern browsers
  • PNG → JPEG: if you have a large PNG photograph and don’t need transparency
  • Any → PNG: if you need a lossless version for further editing

Privacy

Your images never leave your browser. All conversion happens locally using the HTML5 Canvas API.

Controle de Qualidade

O controle deslizante de qualidade é exibido quando o formato de destino é JPEG ou WebP (ambos com perda). A qualidade varia de 1 (máxima compressão) a 100 (mínima compressão). Um valor de 80–90 é geralmente um bom equilíbrio entre tamanho de arquivo e fidelidade visual.

Para saída PNG, a qualidade não se aplica — PNG é sempre codificado sem perda.

Tratamento de Transparência

JPEG não suporta transparência. Ao converter de um formato que pode ter pixels transparentes (PNG, WebP, GIF) para JPEG, as áreas transparentes são preenchidas com a cor de fundo selecionada (branco por padrão). O seletor de cor de fundo só é exibido quando essa situação se aplica.

Comparação de Formatos

JPEG

  • Melhor para fotografias e imagens complexas com muitas cores
  • Não suporta transparência
  • Amplamente suportado em todos os dispositivos e plataformas
  • Tamanhos de arquivo pequenos para fotografias

PNG

  • Melhor para gráficos com bordas nítidas, texto e logotipos
  • Suporta transparência total (canal alfa)
  • Codificado sem perda — sem degradação de qualidade
  • Tamanhos de arquivo maiores que JPEG para fotografias

WebP

  • Formato moderno desenvolvido pelo Google (2010)
  • Suporta compressão com e sem perda
  • Suporta transparência
  • Tipicamente 25–35% menor que JPEG e 20–30% menor que PNG com qualidade similar
  • Suportado por todos os navegadores modernos (Chrome, Firefox, Safari 14+, Edge)

Quando Converter

  • JPEG → WebP: se você quer arquivos menores para entrega web e seu público usa navegadores modernos
  • PNG → JPEG: se você tem uma grande fotografia PNG e não precisa de transparência
  • Qualquer → PNG: se você precisa de uma versão sem perda para edição adicional

品質制御

品質スライダーは変換先がJPEGまたはWebP（非可逆）の場合に表示されます。品質は1（最大圧縮）から100（最小圧縮）まで。80〜90がサイズと品質の良いバランスです。

PNG出力では品質設定は不要 — PNGは常に無損失エンコードされます。

透明度の処理

JPEGは透明度に対応していません。JPEGに変換する際、透明部分は選択した背景色（デフォルトは白）で塗りつぶされます。

変換のタイミング

  • JPEG → WebP: ウェブ配信でより小さいファイルに
  • PNG → JPEG: 透明度が不要な大きなPNG写真に
  • 任意 → PNG: 編集用の無損失バージョンが必要な場合

プライバシー

画像はブラウザから一切送信されません。すべての変換はローカルで行われます。
